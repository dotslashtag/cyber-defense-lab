# EVTX Hunter

Triage Windows event logs from the command line. Point it at `.evtx` exports or a
Wazuh archives export and it will:

1. **Hunt** with the Sigma rules in [`detections/sigma`](../../detections/sigma),
   including correlation rules such as "4+ discovery tools on one host in 10 minutes".
2. **Rebuild process trees** from Sysmon Event ID 1, so you see `explorer → cmd →
   powershell → rundll32` instead of a flat list.
3. **Write a triage report** (Markdown) or a **JSON payload**, and optionally POST
   it to a webhook (for example n8n, which then opens a TheHive alert).

## Install

```bash
pip install -e tools/evtx-hunter          # from the repo root
evtx-hunter --version
```

## Use

```bash
# Hunt with the repo's Sigma rules and print a Markdown report
evtx-hunter hunt tools/evtx-hunter/samples/op002-style-archives.json

# Several inputs, only high/critical rules, report to a file
evtx-hunter hunt Sysmon.evtx Security.evtx --min-level high -o report.md

# JSON for scripts, or send findings to n8n
evtx-hunter hunt archives.json -f json -o findings.json
evtx-hunter hunt archives.json --webhook https://n8n.example/webhook/evtx-hunter

# Process tree only, limited to branches that touch rundll32
evtx-hunter tree Sysmon.evtx --grep rundll32
```

| Option | What it does |
|---|---|
| `-r, --rules` | Sigma file or folder (repeatable). Default: `detections/sigma` found from the current folder up |
| `-l, --min-level` | Ignore rules below this level (default `low`) |
| `-f, --format` | `markdown` (default) or `json` |
| `--webhook URL` | POST the JSON findings to a URL; skipped when there are no findings unless `--send-empty` |
| `--fail-on-findings` | Exit 1 if anything is found (for scripts) |
| `--no-tree` | Leave the process tree out of the report |

## Getting logs out of the lab

- **EVTX from a Windows host:**
  `wevtutil epl Microsoft-Windows-Sysmon/Operational C:\Temp\Sysmon.evtx` and
  `wevtutil epl Security C:\Temp\Security.evtx`.
- **Wazuh archives:** on the manager, `/var/ossec/logs/archives/archives.json`
  (current day) or the dated files under `archives/YYYY/Mon/`. Both
  `archives.json` and `archives.log` lines are accepted.

## Sample

[`samples/op002-style-archives.json`](samples/op002-style-archives.json) is a
**synthetic** 26-event Wazuh export modelled on lab operations OP-002/OP-003: a
native discovery burst, `reg.exe` Run-key persistence, PowerShell with
ExecutionPolicy Bypass launching rundll32, a blocked Defender change, and a
workstation-to-workstation logon, mixed with normal activity (OneDrive's own Run
key, the Wazuh agent's `net user`, local logons). It is generated by
[`make_sample.py`](samples/make_sample.py); the resulting report is
[`samples/op002-style-report.md`](samples/op002-style-report.md).

## Tests

```bash
pip install -e "tools/evtx-hunter[test]"
pytest tools/evtx-hunter/tests
```

The same Sigma evaluator (`evtx_hunter/sigma_eval.py`) also runs the
detection tests in `detections/tests`, so the engine that validates the rules is
the one that hunts with them.

## Limits

- Supports the Sigma features the lab's rules use (wildcards, `re`, `cidr`,
  numbers, `value_count`/`event_count` correlations). Anything else raises an error
  instead of silently not matching.
- `python-evtx` is pure Python: about 200 events per second. For large exports,
  filter with `wevtutil` first or use the Wazuh JSON.
- Process trees need Sysmon Event ID 1 (Security 4688 has no process GUIDs).
